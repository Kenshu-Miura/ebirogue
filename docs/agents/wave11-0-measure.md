# wave11-0: 段11の計測の準備（expert のベースラインとレポートの項目）

段11（BOT の強化 → クリア率の調整）の最初の作業。**1人で先に行い、統合してから 11-A/B/C を始める**（3人が同じ `sim_test.go` のレポートを触らないため）。

最初に `AGENTS.md`、`docs/agents/README.md`、`docs/agents/STATUS.md`、`docs/agents/feature-completion-plan.md`（「段11」）を読むこと。

## 背景

- クリア率の目標（開発者の決定、2026-10-21 に変更）: expert BOT で **初級 80%・中級 45%・上級 5%** 前後。判定は各難易度500冒険。
- 今のベースライン（`reports/baseline.json`）は全性格の1512冒険で、expert は1区分84冒険しかない。84冒険では中級の1区分のばらつきが ±5pt を超えるので、段11の判定には使えない。
- 段7〜10で増えた要素（新しい薬・杖・壺、地形、モンスターハウス、店）を BOT がどれだけ使えているかが、今のレポートでは分からない。

## やること

### 1. expert だけのベースラインを別のファイルに持つ

- `reports/baseline-expert.json` を作り、git で追跡する（`.gitignore` の `!/reports/baseline.json` の下に `!/reports/baseline-expert.json` を足す）。
- 作り方（既存のフラグだけで足りる）:

```bash
go test -run TestSimBatch -count=1 -timeout 0 . -args -sim.persona=expert -sim.runs=1500 -sim.difficulty=all -sim.baseline=reports/baseline-expert.json -sim.writebaseline -sim.out=reports
```

- 段11の以後の比較はすべてこの形（`-sim.baseline=reports/baseline-expert.json`、書き込みなし）で行う。全性格の `baseline.json` は従来どおり段の統合時に取り直す。
- ベースラインのファイルに、取ったときのコミットとフラグが分かる項目が無ければ足す（後で「何と比べたか」を確かめられるように）。

### 2. レポートに段7〜10の要素の項目を足す（`sim_test.go`、性格別）

ゲームのコードは変えない。BOT の判断も変えない（同じシードで、追加前と勝敗・到達階・死因が完全に一致することを確かめる）。

| 項目 | 中身 | 使う担当 |
|---|---|---|
| 新しい道具の使い方 | 道具の ID ごとに「拾った」「使った（飲む・振る・投げる・読む・入れる）」「持ったまま死んだ」回数。対象は 205〜221 の薬・杖と 225〜232 の壺。数の多い順の表 | 11-B |
| モンスターハウス | 自然生成のモンスターハウスがあった階の数・初めて入った回数・入ったときの HP の割合と所持品の数・中で死んだ回数・入ってから出るまで（または階を降りるまで）のターン | 11-A |
| 地形 | 地形（水路・割れた壁・隠し通路）のある階と無い階の、1階あたりの滞在ターン・突風・餓死。割れた壁を壊した回数・隠し通路を見つけた回数 | 11-A・11-C |
| 店 | 店のある階に着いた回数・店に入った回数・買った・売った回数と金額・死亡時の所持金（中央値） | 11-C |
| 探索 | 階段を見つけてから降りるまでのターン、降りたときの HP の割合と満腹度 | 11-C |

- 項目は既存の「性格別の食料と滞在」などと同じ形の Markdown の表にし、ベースラインとの差分の表にも主な数を出す。
- 記録は BOT の行動（`bot.act`）とゲームの状態から読む。ゲームに記録用の変数を足す必要があれば、セーブに入らない `Game` のフィールドにとどめる。

### 3. 今の expert の現状を報告する

- 上の1のコマンドで取ったベースラインの要点（難易度別のクリア率・平均到達階・到着時の平均レベル〔10・20・30階〕・死因の上位10・判断ミス死・新しい項目の要点）を完了報告に書く。
