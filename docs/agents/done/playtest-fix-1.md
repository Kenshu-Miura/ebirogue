## 原因と修正

1. 仮眠の入室判定が毎ターン同室の敵に抽選していた。`Game.previousPlayerRoomID` と `roomIDAt`（部屋の内側、壁・通路は -1）を追加し、前回と異なる部屋に入ったときだけ抽選する。新規冒険・階移動の生成後に到着の抽選を1回実行し、その後の最初のターンでは繰り返さない。再開時は現在の部屋 ID で初期化し、セーブ形式は変更しない。乱数は既存の `g.random()`。隣接時の毎行動50%抽選は変更していない。
   - `applyDamageToEnemy` で仮眠（Sleep == -1）を解除する。Sleep > 0 の挙動はそのまま。直接 `Health -=` しているプレイヤー由来の真空斬りは既に `wakeFromSleep` を呼んでいたため変更不要。追加指定により敵同士の近接攻撃でも仮眠を解除する。敵の範囲爆発・遠距離攻撃の爆風は既に Sleep = 0 にしており、その挙動をテストで固定した。
2. C の先行する持ち物処理が足元メニューだけを閉じ、説明などの状態を残していた。`closeAllMenus` に表示・説明テキスト・対象選択・選択位置・戻り先をまとめ、足元・持ち物・設定・中断確認・ヘルプ・記録・空の持ち物・キー設定の C 処理から呼ぶ。メッセージ履歴でも C で同じ処理を呼ぶ。足元の説明の描画にも `ShowGroundItem` の条件を加えた。
3. 射線中も中央に持ち物と不透明な行動メニューが重なっていた。プレビュー中は持ち物一覧を描かず、選択した道具名だけを上端寄りの小窓（170,50〜490,76）に表示する。足元の道具名も同じ場所へ移す。行動メニューは右端へ寄せ、5項目の場合は (480,230)〜(630,340)、4項目なら (480,250)〜(630,340)。中央の海老さんと8方向の射線、HUD、メッセージ欄を避ける。射線のない項目は従来の中央配置を使う。
   - 射線の判定は `currentItemActions` / `currentGroundItemActions` の項目名を使用する。投げる・撃つは10マス、杖の使うは30マスで壁のマスまで表示。壺の「出す」・かつおぶしの「かじる」では表示しない。
   - 高さは `項目数 × 20 + 10`。5項目の説明が枠の下端にかからない。

最初に `go test -run 'TestSleeping|TestPlaytest' -count=1 .` を実行し、同室滞在での起床・ダメージでの仮眠解除・C の閉じ残し・壺と食べられる武器の「出す/かじる」と「投げる」の誤判定が失敗することを確認した。C のテストは仮想入力のフレーム更新を補ったうえで元の `input.go` に戻して再実行し、実際の C 入力でも失敗することを再確認した。配置テストも旧配置 (220,190)〜(420,290)・高さ100の計算で実行し、中央のプレイヤーマスとの重なりで失敗した。高さの専用テストも旧計算で5行目の下端への重なりを再現した。いずれも修正版へ戻し、以下が成功した。

- `sleep_wake_test.go`: 入室抽選を外した敵は同室で滞在・別の敵を攻撃しても眠り続け、余分な起床乱数を使わない。通路→同じ部屋への再入室、部屋A→B、壁を通路扱いする境界、隣接時の外れ後の再抽選、フロア到着の1回だけの抽選、近接・投擲・魔法弾・黒炎弾のダメージによる起床、通常睡眠の維持、中断データの復元で起床抽選も乱数消費もないこと。

## 実機で見た目と操作を確かめる手順

実機の描画確認は指示書どおり開発者が行う。以下は既定キー。キー設定を変更した場合は対応するキーに読み替える。

1. `go run .`、難易度を選んで冒険を始める。部屋に入り、隣接していない仮眠の敵が残った場合、X+Zで足踏みしたり別の敵と戦ったりする。同室にとどまるだけでは起きず、部屋を出て戻ると再抽選する。隣接すると毎ターン抽選、近接や道具のダメージが当たると必ず起きる。
2. 道具の上で C→「足元」→「説明」を選ぶ。Cで全部閉じ、説明窓が残らないことを確認する。もう一度 C→「足元」を開くと、「拾う」からの通常メニューが見える。C→「道具」→道具→「説明」→Cでも全て閉じる。
3. C→「道具」→通常の道具を選び「投げる」に合わせる。持ち物一覧が消え、名前の小窓が上端寄り、行動メニューが右端に見え、中央の海老さんと射線が見える。方向の異なる場面でも試す。上下で「置く」「説明」に移すと射線が消え、中央配置に戻る。
