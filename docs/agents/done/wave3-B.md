## 仕様の判断と統合時の注意

- 依頼冒頭が wave3-B、別担当が wave3-A と明示されているため、読む順序の4番の wave3-A は関連担当の確認として読み、実装のID・Type・画像・フック・テストは wave3-B に従った。
- 呪いの鍋ぶたは個別指示書の決定どおり「この盾が呪われている間、被ダメージ4/5」。計画のパワー+1は採用しない。
- 小判・鉄塊は元ダメージ1のとき最低1の制約で軽減できないため、代価を払わない。回避・反射でも払わず、被害判定時にはまだ支払わない。
- 悟りの盾は最大満腹度を上書きしない。満腹度0を1に回復する効果もない。
- 悟りの上限を入れた箇所: `action.go` の所持品装備と足元装備の成功分岐、`itemeffects.go` の食料による最大満腹度増加・通常回復、`itemeffects_rotten_food.go` の腐った食料の回復。
- `equipment_abilities.go` は満腹度減少処理だけ変更した。能力定数と登録表には追記していない。`satietyLossInterval` が0（減少なし）を返すため、ゼロ除算回避に必要な `shouldReduceSatiety` の正の間隔ガードも追加した。指示書の「この1か所」の範囲を、同じ減少判定の2関数に最小限拡張している。
- 共有ファイルは既存行を並べ替えず追記。上記 `shouldReduceSatiety` の式のみゼロ除算回避のため置換。
- **wave3-A のかつおぶしのかじる処理で、満腹度を増やした直後に `g.capSatietyForSatori()` を呼ぶこと。** こちらのブランチにはかつおぶしが無いため、統合担当が追加する。wave3-Cや今後の指輪にも満腹度を増やす処理があれば同じ接続を確認する。
