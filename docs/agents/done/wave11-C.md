### 2. 店で売る・買う（expert だけ、`bot_shop_test.go`）

- **売る（`shopsell`）**: 店の中で、`itemValue` が 10 以下（`botSellMaxValue`。不利なカード・呪われた予備・弱い予備の武具・使えない指輪・回数0の杖・要らない壺など）の道具を空いた床に置き、売却の窓で「売る」を選ぶ（`closeWindows` → `shopPromptKey`）。満杯で買う商品があれば、それより価値が5以上低い道具も売る。
  - 置く床は、出入口のそば（8近傍）を避け、置いても店の空いた床と出入口がすべてつながったままのマスだけ（`shopStaysConnected`）。最初の計測で、売った品で出入口や自分の周りをふさぎ、商品のマスを通れずに閉じ込められて突風で倒れる冒険が 199 件出たため。
- **買う（`shopbuy`）**: 見えている商品のうち、所持金－未払い＋売る予定の道具の売値で買えて、価値の一番高いもの（`bestPurchase`）へ向かって拾う。
  - 買う価値（`buyValue`）: 食料（壺の中を含めて3つ未満）100、回復の道具（expert が使う 173・2・28・3・29・44、2つ未満）90、今より強い武器（攻撃力＋強化値が2以上上）・盾（`bestEquipment` と同じ乗り換えの条件）80、ほかは `keepValue` が 50 以上（不利な道具は除く）。呪い・強化値マイナス・満腹度を使う装備は買わない。
  - 拾ったらすぐ店主の隣へ行き、向いて Z で話しかけて払う（支払いの窓は `shopPromptKey` が「払う」）。払えない分は店の中に置いて返し（`returnUnpaidItem`）、同じ階では買いに戻らない（`shopRejected`）。
  - 近く（5マス）に起きている敵がいるときは売買しない（払いに行くのは隣に敵がいなければ続ける）。
- **お金（`money`）**: 今のゲームは所持品が満杯だとお金も拾えないので、満杯で見えているお金へ行けるとき、価値10以下の道具を置いてから拾う。
  **満杯でもお金は拾える仕様に決まった**（下の「開発者の決定とマージ時の作業」）。ゲームを直したらこの改善は要らなくなる。
- **換金の壺は使わない**: 換金の壺の額は店の売値（`itemSellPrice`）と同じで、店で売るより得になるのは「店の無い階で、要らない道具を持ち歩く枠を空けたい」ときだけ。お金の使い道は店だけで、店のある階に着くのは約11階に1回なので、壺の枠と手間に見合う場面がはっきりしない。

### 3. 探索の切り上げと降りる前の休憩（expert だけ、`bot_explore_test.go`）

- **切り上げ（`leavefloor`）**: `expertWantsToDescend` に、「階段のマスを見つけていて（`Visited`）、見えている拾う価値のある道具が無く、滞在 500 ターン超（`botLeaveFloorTurns`）か満腹度＋手持ちの食料の見積もりが 100 未満（`botLeaveFloorSatiety`）」なら降りる条件を足した（見えている食料を先に拾う・食料が50以下なら降りる、の既存の条件の後）。
  - 突風の前: 滞在 1000 ターン超（`botGustRushTurns`）でふつうの経路で階段へ行けなければ、敵・罠を押しのける経路で向かう（`expertRushStairs`、目的地の選択の直前）。
- **降りる前の休憩（`restbeforestairs`、既定で切ってある）**: 降りたいとき、HP が満タンでなく、満腹度 30 超・滞在 1000 ターン未満・回復不能でなく・6マス以内に敵がいず・射線にいなければ、階段の上で足踏みする（1階あたり80ターンまで）。階段の確認の窓は X で閉じてから休む。

## 開発者の決定とマージ時の作業

**決定（開発者、2026-10-22）: 持ち物が満杯でもお金は拾える。** お金は持ち物の枠を使わず所持金に入るため。
今のゲームは `item.go` の `PickupItem` が、お金も含めて持ち物の数（20未満）で拾えるかを決めているので、満杯だと「持ち物がいっぱいで〜を拾えなかった」になる。このブランチではゲームのコードを変えない指示だったので直していない。統合担当がマージ時に次を行う。

1. **ゲームを直す**: `PickupItem`（`item.go`）で、足元の道具がお金（`*Money`）なら持ち物の数にかかわらず拾う（`xPressed` でない通常の分岐。聖域のカード・拾得禁止の扱いは今のまま）。メニューの「足元」→「拾う」の経路も満杯でお金を拾えるか確かめ、拾えなければ同じように直す。
2. **回帰テスト**: `regression_test.go` に「持ち物が20個のときお金の上に乗ると所持金が増え、持ち物の数は変わらない」テストを足す（通常の歩行と、足元のメニューの両方）。
3. **BOT を合わせる**: `bot_shop_test.go` の `makeRoomForMoney`（`money`）は満杯でお金を拾うために道具を手放す処理なので、ゲームを直したら消す（`expertStep` の 5b の呼び出し・定数 `botMoneyDropValue`・`visibleMoneyGoal` も）。代わりに、満杯でもお金を拾いに行くよう `worthPicking`（`bot_expert_items_test.go`）でお金を満杯の判定から外す（`b.inventoryFull()` の入れ替えの条件をお金には掛けない）。`itemGoal`（`bot_test.go`）も満杯だと何も目標にしないので、お金だけは満杯でも目標にする。
4. **計り直す**: 拾えるお金が増えると BOT の乱数の消費と結果が変わるので、expert 1500冒険（`-sim.persona=expert -sim.runs=1500 -sim.difficulty=all -sim.baseline=reports/baseline-expert.json`）と全性格の `TestSimBatch -sim.runs=300 -sim.difficulty=all` を回し、泥棒0・違反0とクリア率を確かめる（このブランチの `money` を切った計測は 初級 80.2%・中級 39.6%・上級 7.0% で、ほかとの差はばらつきの内）。ベースラインの取り直しは 11-D の前に統合担当が決める。
5. **ドキュメント**: STATUS.md の「確定した仕様」に上の決定を書く。IMPLEMENTED_FEATURES.md の道具・お金の項に「持ち物が満杯でもお金は拾える」を足す。AGENTS.md の BOT の説明の `money` の文は消す。
