# bot-food: BOT の食料の扱いの改善

ブランチ: `agent/bot-food`。ゲームの数値・本体のコードは変えていない（触ったのは `bot_test.go`・`bot_expert_test.go`・`sim_test.go` と新しい `bot_food_test.go` だけ）。BOT は今までどおり仮想入力で本物のメニュー経路を操作し、乱数も決定的なまま。

## 結論

- **餓死 231 → 32**（1512冒険）。random（バグ探し用のランダム入力。変えていない）の14件を除くと 217 → 18。
- 主な原因は BOT の判断ミスだった: 遅い性格は**所持品が満杯で床の食料を拾えない**、**同じ階に閉じ込められる**（階段への道を敵・罠にふさがれると足踏みし続ける）、**長居して突風に飛ばされる**（突風死 78 → 4）。expert は**空腹になると階段へ直行して、見えている食料も素通りしていた**（床の食料を拾った割合 0.33）。
- expert の強さはほぼ変わらない（1500冒険でクリア率 19.8% → 19.5%、初級 57.8% → 57.8%）。餓死は 166 → 35。
- 残った expert の餓死（1500冒険中35）は、食料の出ない階が続いた冒険がほとんど（35件中31件で3階以上続けて到着時の床に食料が無い）。BOT 側でこれ以上減らすのは難しい。ゲーム側の対応の意見は最後に書く。
- **計測への影響（要注意）**: 以前は空腹の expert が階段へ直行して深い階まで到達していたため、平均到達階が水増しされ、到着時レベルは低く出ていた。改善後の expert の到着時レベルは 10階 17.0 → 20.1（目標 13〜16 をさらに超える）。STATUS の 5c（到着時レベルの合わせ方）はこの値で判断し直す必要がある。

## 変更内容

### 1. 計測（`sim_test.go`）

`TestSimBatch` のレポートに「食料と滞在（性格別、全難易度）」と「段4の敵（ID 108〜125）による死亡」を追加した。冒険ごとの JSON（`simOutcome`）にも次を残す。

| 項目 | 内容 |
|---|---|
| `FoodPicked` | 拾った食料の数（`RunStats` の Food の Picked。敵が落とした食料も含むので、割合が1を超えることがある） |
| `FloorFood` | 各階に初めて着いたときに床にあった食料の数（i 番目が i+1 階） |
| `FloorStays` | 階段・落とし穴で離れた階の滞在ターン（終わった階は含まない） |
| `StarveTurns` | 終了時に満腹度0が続いていたターン数 |
| `InventoryFull` | 終了時に所持品が満杯だったか |

性格別の表は、クリア率・平均到達階・餓死・床の食料・拾った数と割合・1階あたりの滞在ターン・餓死時の満腹度0の継続ターン・餓死時に所持品が満杯だった数を出す。集計の項目は `simGroupStats` に足したので、古い `baseline.json` との差分の表は今までどおり出る（新しい項目は比較しない）。

### 2. 食料の扱い（全性格、`bot_test.go`。random は使わない）

| 改善 | 内容 |
|---|---|
| 見えている食料を優先 | `visibleFoodGoal`: ミニマップに表示されている（人に見えている）床の食料を、ボスの次に目指す（敵・ほかの道具・探索より先）。見えている食料が拾えるうちは階段を降りない |
| 満杯なら道具を手放す | `makeRoomForFood`: 所持品が満杯で見えている食料へ行けるとき、価値の低い道具を足元に「置く」（足元がふさがっていれば「投げる」）。手放す順は不利なカード → 予備の武器・盾 → 指輪・矢 → 分類の無い道具 → 強化 → 攻撃・逃走。装備中・食料・回復は手放さない。食料を2つ以上持っていれば強化・攻撃・逃走の道具は手放さない。手放した道具は同じ階では拾い直さない（`discarded`、階とテンプレート ID で記録するので中断・再開でも消えない） |
| 足元の食料を拾う | `pickUpHere`: 満杯で拾えなかった食料の上で空きができたら、C →「足元」→「拾う」で拾う |
| 食べ方 | `eatIfStarving`: 普通の食料を先に食べ、腐ったウインナーは最後に回す。食べる目安は従来どおり（expert 20・ほか15） |
| 空腹なら階段へ | `hungry`（満腹度30以下で食料を持っていない）なら、見えている食料の次に階段を目指し、未探索の部屋より先に降りる |
| 閉じ込められない | 通路を敵・発見済みの罠にふさがれて行き先が無いときは、敵を倒し罠を踏んで階段（無ければ未探索）へ進む（expert にあった処理を全性格に） |
| 長居しない | この階に500ターン以上いたら、敵を追うより先に階段へ向かう（以前は aggressive・itemUser は敵を追い続けて突風に飛ばされていた） |
| 満腹度を減らす装備 | 重甲の盾（69）と満腹度を使う武器・盾（136・137・155・156・159）は、空いている枠でも装備しない（expert は以前から） |

### 3. expert 固有（`bot_expert_test.go`）

| 改善 | 内容 |
|---|---|
| 見えている食料 | 移動の目的地に「toFood」を、遠距離の敵の次・経験値になる敵より前に入れた。見えている食料が拾えるうちは降りない（この階に700ターン以上いる場合を除く） |
| 空腹で階段へ直行するとき | 以前と同じく満腹度と手持ちの食料の合計が50以下なら探索を切り上げるが、見えている食料は拾ってから降りる。閾値は試して決めた（下の「試したもの」） |
| ボス階 | ボスへの道を呼ばれた手下にふさがれていたら、手下を倒して進む。食料が尽きたら HP が減っていてもボスに挑む（ボス階は倒すまで降りられないので、以前は手下の周りをうろついて餓死していた） |
| ふさがれた道 | 降りたいときは、敵・罠を越えて進む先を未探索より階段を先にする |

### 4. 段4の敵への対処（expert）

**判断は人に見える姿を基準にした**（`apparentEnemyID` = `enemyAppearance(e).ID`）。化けたミミックダコはその化けた姿の敵として扱う（ウチカエシエビに化けていれば撃たない）。正体（`MonsterDefinitions[e.ID]`）は見ていない。帯電・膨張の状態（`Enemy.Flag`）は画面のメッセージで分かるので読んでよいとした。なお、ほかの判断（強敵かどうかの HP・攻撃力の見積もり）は以前から正体の能力値を使っている。

| 敵 | 対処 |
|---|---|
| ウチカエシエビ系（123〜125） | 矢を撃たない、状態異常の薬・ジェノサイドのカードを投げない（`targetInLine` で直線上の最初の敵が打ち返す敵なら、その方向を選ばない） |
| 膨らんだフクレフグ系（108〜110） | 一撃で倒せないなら殴らずに離れる。経験値のために近づく対象からも外す。離れたところからの射撃はする |
| 帯電したシビレエイ系（114〜116） | 同上（隣で殴ると放電） |

ただし、破裂・放電のダメージ（`fukureFuguExplosionDamage`・`shibireEiDischargeDamage`）が今の HP の 1/4 以下なら殴る。また6ターン続けて離れたら殴る。最初はこの2つが無く、通路にいる膨らんだフグから離れては階段へ向かって戻る行き来を続け、突風で7回倒れた（1500冒険）。

### 5. テスト（`bot_food_test.go`）

所持品が満杯でも不利なカードを置いて食料を拾い、回復の薬は手放さず、置いたカードを拾い直さない（4性格）／足元の食料をメニューから拾う／普通の食料を腐ったウインナーより先に食べる／重甲の盾を装備しない／段4の敵の見分け（化けたミミックダコを含む）／膨らんだフグから離れる／ウチカエシエビに矢を撃たない。

expert の「満腹度と手持ちの食料の合計がこれ以下なら探索を切り上げて降りる」閾値（expert 1500冒険。食料の改善〔2・3の toFood まで〕だけを入れ、ボス階と段4の対処を入れる前の段階で測った）:

| 閾値 | 餓死 | クリア率 | 10階の到着時Lv |
|---:|---:|---:|---:|
| 30 | 72 | 19.5% | 20.9 |
| **50（従来どおり、採用）** | 48 | 19.9% | 20.1 |
| 70 | 35 | 18.9% | 19.4 |

探索を早く切り上げるほど餓死は減るが、経験値が減ってクリア率が下がる。指示書の目安の30は餓死が増えた（探索で食料を探しきれないまま満腹度が尽きる）。性格の性質を保つため従来の50のままにした。

## 残った餓死の分析

| | 改善前（expert 1500） | 改善後（expert 1500） |
|---|---:|---:|
| 餓死 | 166 | 35 |
| うちボス階（10・20階） | 58 | 12 |
| 食料を1つも拾わずに餓死 | 68 | 8 |
| 3階以上続けて到着時の床に食料が無かった | 122 | 31 |
| 1〜3階の床に食料が無かった | 47 | 13 |
| 餓死した冒険で、到着時の床に食料が無かった階の割合 | 60% | 70% |

- 全冒険で、到着時の床に食料が無い階は 59%、1階あたりの食料は 0.51個。1〜3階に1つも食料が無い冒険は 1500中355（24%）。
- 改善後に残った餓死は、食料の出ない階が続いた冒険に偏っている（到着時に食料が無い階の割合 70%、全体は 59%）。到着時の床に見えた食料は拾えるようになった（拾わずに餓死 68 → 8）が、空腹で降りる途中の階で入らなかった部屋の食料は見えないので拾えない（人が遊んでも同じ）。
- 性格別で餓死が減らなかったのは random（14 → 14）だけで、これはランダムに入力する性格なので変えていない。
- ほかに見つかった BOT の弱点（今回は直していない）: expert が階段への道を罠にふさがれると、罠（ワープなど）を踏んで別の場所へ飛ばされ続けることがある（突風死1件、1500冒険）。

### ゲーム側の対応についての意見

- **急ぎの対応は要らない**と考える。BOT の判断ミスを直すと、expert の餓死は 1500冒険中35（2.3%）、全性格（random を除く）で 1512冒険中18 になった。以前の「餓死が段ごとに増える」は BOT の拾い残しと閉じ込めによるもので、食料の量の問題ではなかった。
- 残る餓死は「食料が出ない階が続く」ばらつきによるもので、SFC シレン系の満腹度の圧力として許容できる範囲と思う。減らしたい場合は、全体の量を増やすより**ばらつきを抑える**ほうが的を絞れる。
  1. 食料の出ない階が続かないようにする（例: 直前の2階で食料が出なかったら、その階に1つ置く）。残った餓死の 31/35 に直接効く。
  2. 序盤（1〜3階）に1つ保証する。残った餓死の 13/35 に効くが、効果は1より小さい。
  3. 食料の重みを増やす（starvation-analysis.md では +25% で餓死 −13%）。拾い残しが無くなった今はもう少し効くはずだが、ほかの道具が減る。
- 階層別のアイテムの出現テーブル（STATUS の 5b）と一緒に決めるのが自然。
- それより先に、**expert の到着時レベルが目標をさらに超えた**（10階 20.1、目標 13〜16）ことを 5c の判断に反映してほしい。
