## 仕様の判断

- 回復の指輪は共通基盤の呼び出し順どおり自然回復・通常の満腹度減少の後に発動する。通常の減少で満腹度が0になったターンは追加回復しない。20ターン目には追加回復の判定後に追加の満腹度を引く。
- 胃拡張・胃縮小は最大満腹度だけを変更し、現在満腹度を増やさない。最大を超えた分は切り詰める。満腹度を増やす新しい処理はなく、`g.capSatietyForSatori()` が必要な新経路はない。
- master の悟りの盾は最大満腹度の値を変更せず、現在満腹度を1へ制限する実装。これを維持し、胃拡張と併用すると最大満腹度は125、現在満腹度は1になることをテストした。
- 能力 ID の定数は指示書どおり `!test` のファイルに置く。タグなしの純粋関数では対応する文字列を使い、両ビルドの単体テストと通常ビルドのテンプレートテストで対応を確認する。
- 気配察知・透視は未発見の擬態中の敵を感知しない。既存の「同じ部屋／隣接／発見済み」の表示は維持し、既存の擬態アイテム・階段のミニマップ表示を変更しない。道具の感知は `PlayerDiscovered` を変更しない。
- 鑑定師は拾った道具本体だけを識別し、お金と壺の中身は対象外。
- 浮遊は位置から罠を探す入口で処理し、`stepOnTrap` の直接呼び出しや正面の罠調査を変更しない。
- 高飛びは既存のワープの罠を使う。爆発・持ち物や小銭の落下・罠の増加は Action の `Execute` 内で状態を変更する。爆発の撃破は敵スライスを逆順に処理し、経験値と撃破フックを共通処理へ任せる。
- 罠増しは床の空き候補から重複なしで選び、候補不足なら置ける分だけ置く。階段・道具・罠・プレイヤーの位置は除外。敵の存在は指示書の除外条件にないため除外しない。ボス階・最終階は共通の `availableTrapIDs` により落とし穴を除く。
- 指示書のテスト例にある「混乱の罠」は現行テーブルにないため、混乱薬と免疫の共通判定で検証した。睡眠ガス、毒ヘビ、毒矢、さびの罠、ノロイガニは実際の効果経路でも確認した。
- セーブの能力一覧はテンプレートから再生成し、呪い・識別・最大満腹度は既存の保存値を復元する。おはらい後に保存しても、生成時の呪いが復活しないことを確認した。

## 未決事項・推奨案

実装を止める未決事項はない。確率・数値は指示書を採用した。

- 出現重み：3のまま統合を推奨。選択肢は3を維持、2へ抑制、階層別テーブルで調整。今回の計測では指輪の出現増と餓死の非増加を確認したが、個々の指輪の入手機会はプレイヤーの試遊も必要。
- 高飛び・爆発・垂れ流しの確率：指定値を維持する案を推奨。引き下げる案もあるが、expert BOT は指輪を装備せず、今回の集計だけでは装備時の有利・不利を評価できない。試遊や指輪専用の計測を経て開発者が判断する。
- 回復の指輪と悟りの盾：指定どおり追加の満腹度減少は発生する。悟り装備でも20ターン目に1→0になり得る。回復の代価を維持する案を推奨。代価も無効化する案は今回の指示の範囲外。
- 最低最大満腹度：通常の初期最大100と指輪2枠では最低50。将来、別の要素で最大満腹度を25未満にする場合、下限1への切り詰めを経た装備解除が元の値に厳密に戻る仕組みが別途必要。現行の指示どおり下限1を採用し、新しい可変フィールドは加えていない。

wave4-B/C の敵とヘルプを統合した後は、統合担当が通常・スタブテストとシミュレーションを再実行する。
