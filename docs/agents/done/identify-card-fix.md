# identify-card-fix: 真実の眼のカードの振り直し不具合

ブランチ: `agent/identify-card-fix`（master `d3d5787` から分岐）

## 不具合

真実の眼のカード（アイテム ID 11）は、使った時点で `rollIdentifyAll`（1/5）を振り、外れると識別対象の選択画面を開いていた。
この画面を `X` で取り消すとカードもターンも消費されないため、使い直して 1/5 を何度でも振り直せ、必ず「持ち物すべてを識別」にできた
（BOT の計測では 304 枚に対して 1500 回使用。`docs/agents/bot-strategy-research.md`）。

調べたところ、ほかに次の不具合もあった。

- 対象を確定しても `isActioned` を立てておらず、識別してもターンが進まなかった（道具の使用は1ターンという仕様に反する）。
- 足元のカードを「使う」と、`executeGroundItemAction` が直後に `isActioned = true` と `GroundItemActioned = false` にするため、
  選択画面が開いたままターンが進み、確定するとカードの床の添字を持ち物の添字として扱って**持ち物の別の道具を消していた**。
  また、確定時の対象を `determineItemSource` で取っていたため、足元から使ったときはカード自身を「識別」していた。

## 直し方と判断

候補は (a) 1/5 の判定を対象を選んだ後（`executeItemIdentify`）に行う、(b) 外れた時点でカードを消費し、取り消しても消費済みにする、の2つ。**(a) を採用した。**

理由:

1. 振り直しの原因は「判定」と「確定」の間に、無料で戻れる操作（取り消し）があったこと。判定を確定の後ろへ移せば、取り消しは何も振らない操作になり、振り直しが原理的にできなくなる。
2. (b) は誤操作で選択画面を閉じただけでカードが消える。白紙のカード・ソーセージのカードなど、ほかの対象選択（`itemTargetEffect`、`consumeTargetCard`）は「確定前に閉じても消費しない」で統一されており、(a) はこれと揃う。
3. SFC シレンの識別の巻物に近いのは「全識別かどうかを、使う前や取り消しで選び直せない」こと。(a) なら全識別かどうかは確定して初めて分かり、取り消しで有利な結果を選び直せない（全識別に当たったときは、選んだ道具を含む持ち物すべてが識別される）。原作で選択を取り消したときに巻物が消費されるかは確認していないが、(b) の「取り消しても消費」はこのゲームのほかの対象選択と食い違うので採らなかった。
4. 乱数は従来どおり `g.randIntn` 経由で、確定時に1回だけ引く。取り消しでは乱数が進まないので、同じシード・同じ確定操作なら取り消しを挟んでも結果は同じ（回帰テストで確認）。

変更点:

- `itemeffects.go`
  - `identifyItem`: 判定とカードの消費をやめ、選択画面を開くだけにした。
  - `executeItemIdentify`: 確定時に `rollIdentifyAll(g.randIntn)` を振り、当たれば持ち物すべて、外れれば選んだ道具を識別する。どちらでもカードを消費し `isActioned = true`（1ターン）。足元のカードは床から消し、対象は常に持ち物の選択中の道具にした。
- `action.go`: 足元から使ったとき、`itemTargetEffect` と同じく `useIdentifyItem` でも `GroundItemActioned` を保ち、ターンを進めない。
- `input.go`: 識別の選択の取り消しで `GroundItemActioned` も戻す。足元のカードのときは、選択中の添字がカードの床の添字と同じでも確定できるようにした（持ち物とは別の並びなので比べる意味がない）。

## テスト（`regression_test.go`）

- `TestIdentifyCardCancelCannotReroll`: 使う→取り消しを20回繰り返しても、カードもターンも消費されず、冒険の乱数の状態（`g.rng.MarshalState`）が変わらない。その後に確定した結果は、取り消さずに使った同じシードのゲームと一致し、カードを消費して1ターン進む。修正前のコードでは seed 1 の10回目の使用で全識別が出て失敗する。
- `TestIdentifyCardConfirmRollsOnce`: 確定で選んだ道具は必ず識別され、シードによって「全識別」と「1個だけ」の両方が起こる。
- `TestIdentifyCardFromGround`: 足元のカードを使うと選択画面が開いてもターンは進まず、取り消しでカードが床に残る。確定すると床のカードが消え、持ち物の道具は消えず、選んだ道具が識別される。

確認: `gofmt -w`、`go test -tags test ./...`、`go test ./...`、`go test -run TestSimSmoke -count=1 .` すべて成功。

## BOT 側への影響（統合担当向け）

- 取り消し→再使用で全識別を狙う BOT（`bot_test.go` の `useInventoryItem`）の挙動は、修正後は効果がない（取り消しは何も振らない）。BOT は対象を選んで確定すれば1枚1回で済む。`bot-food` 系ブランチの BOT で使用回数の計測が変わる（1500 回 → 枚数相当）見込み。
- 識別の確定がターンを消費するようになったので、BOT のターン数がわずかに増える。
