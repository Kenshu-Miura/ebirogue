# wave7-B: 入力の記録の保存と再生

ブランチ: `agent/wave7-B-replay`。開始点: 最新の `origin/master` (`b3224c9`)。

## 変更概要

- `replay.go` / `replay_game.go` に記録形式・検証・保存・ヘッドレス再生を追加。
- シード・難易度・セーブ形式のバージョン・ソースの SHA-256 によるビルド識別を保存。ソースを埋め込んでハッシュを計算するため、同じチェックアウトの通常実行・WASM・`go test` が共通の識別になる。配布側で明示する場合は `-ldflags '-X main.replayBuildID=<識別子>'` を通常ビルドと再生テストの双方に指定する。
- 論理キーの押下時間をフレーム単位で記録。同じ押下状態が続く区間は開始時の押下時間と継続フレーム数に圧縮し、押しっぱなし・キー設定変更直後の状態を再現する。キー設定画面だけは割り当て用の物理キー入力も補助情報として保存する。
- `ebirogue_replay_last.json` を冒険の最初のフレーム・60フレームごと・中断/オートセーブ時・死亡/クリア時に更新。終了した冒険は `ebirogue_replays.json` に最大10件保存。両ファイルを `.gitignore` に追加。
- 記録の開始状態と中断再開ごとの開始状態を保存。中断セーブに省略可能な `Replay` を追加し、前の区間の入力も引き継ぐ。中断・オートセーブが Update の途中で行われた場合は、フレームの記録確定後に再保存する。死亡時には中断データを作り直さない。
- `GameSettings.SaveInputReplay` は省略可能な `*bool`。未指定はオンなので旧設定も読める。設定画面の4項目目で切り替える。
- 保存・記録は `persistent` の場合だけ。通常の BOT・テストや再生から書き込まない。セーブ形式のバージョン3は変更していない。
- 各フレームで階・HP・死因・ターン数、乱数状態、プレイヤー/所持品/装備、敵、床の道具/罠、統計、予約出現等を照合。描画が変える明るさは除外。最初の不一致のフレーム、またはバージョン/ビルド違いのフレーム0で停止する。

## 再生の手順

記録と同じソースのチェックアウトで実行する。

```sh
go test -run TestReplayFile -count=1 . -args -replay.file=ebirogue_replay_last.json
```

最後の階・HP・死因・ターン数をテストのログにも表示する場合は `-v` を付ける。

```sh
go test -v -run TestReplayFile -count=1 . -args -replay.file=ebirogue_replay_last.json
```

Linux の画面がない環境では `xvfb-run -a` を先頭に付ける。WASM の記録は同名の localStorage キーの値を JSON ファイルに取り出して渡す。履歴ファイルは配列なので、再生したい1件を取り出して渡す。

## 未決事項・仕様に明記のない判断

- 任意項目の「記録」一覧の印は未実装。履歴には再生データが残るが、一覧への対応付けは統合後の課題とした。
- 冒険の途中でオフにしたらその冒険のメモリ上の入力記録を破棄し、再びオンにしても次の冒険から再開する。不完全な途中記録を完全な冒険として扱わないため。画面にも「次の冒険から」と表示する。既に保存された過去のファイルは自動削除しない。
- 旧セーブに入力記録がない場合は、再開地点を最初の開始状態として記録する。過去の入力は復元できない。
- 異なるソースやビルド識別の記録は互換再生せず拒否する。ソース埋め込みにはルートの Go ファイル（テストを含む）と go.mod/go.sum を使うため、テストだけの変更でも識別は変わる。カスタムビルドタグを使う配布は明示のビルド識別子も変えること。
- 読み込みの上限は1記録64 MiB・合計1,000万フレーム。極端に長い冒険や localStorage の容量超過時の扱いは今後見直せる。保存失敗はログに残す。
- 中断再開は、保存された開始状態から区間ごとに復元する。中断前のすべての区間も順に再生して照合する。ゲーム内の再生UIは指示どおり対象外。
- 実ブラウザの localStorage で長時間保存する操作確認は未実施。WASM ビルドと共通ストレージAPIの利用を確認した。
