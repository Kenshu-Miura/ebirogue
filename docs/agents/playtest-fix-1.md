# 実機確認で見つかった不具合の修正（playtest-fix-1）

開発者が実機（`go run .`）で見つけた3件の不具合を直す。ブランチは `agent/playtest-fix-1`。
原因は指示書の作成時にコードを読んで特定済み（2026-10-15、`1659313` 時点）。行番号は目安なので `grep` で探すこと。

## 1. 仮眠の敵が想定外のタイミングで目覚める

### 仕様（開発者の意図）

フロア生成時に50%の敵は仮眠（`StatusAilments.Sleep == -1`、`map.go`）で置かれる。仮眠の敵が目覚めるのは次の3つだけ。

1. プレイヤーが敵のいる部屋に**入った時**（50%）
2. プレイヤーが敵の周囲8マスに**近づいた時**（50%）
3. プレイヤーから**攻撃を受けた時**（必ず）

### 現象

部屋の中で別の敵と戦っているなど、上の3つに当たらないタイミングで仮眠の敵が目覚める。

### 原因

`monster_spawn.go` の `CheckSleepingEnemyWakeUp` は `AdvanceTurn` から**毎ターン**呼ばれ、プレイヤーが同じ部屋にいる間、毎ターン50%で起こしている。「部屋に入った時」の1回ではなく「部屋にいる間ずっと」判定しているので、部屋で2〜3ターン過ごすとほぼ確実に起きる（2ターンで75%、4ターンで94%）。

### 修正

- 「部屋に入った時」の判定を、**プレイヤーのいる部屋が前のターンと変わった時だけ**にする。
  - `Game` に前のターンにプレイヤーがいた部屋の ID（通路は -1）を持たせ、`AdvanceTurn` で今の部屋と比べる。違う部屋（-1 以外）に入ったターンだけ、その部屋の仮眠の敵それぞれに50%を振る。
  - 部屋 ID を返すヘルパー（`roomIDAt(x, y)` など）を作り、`isSameRoom`（`move.go`）と同じ「部屋の内側」の判定を使う。
  - 通路→部屋、部屋A→部屋B のどちらも「入った」とみなす。同じ部屋に出入りし直せば再び判定する。
- フロアに降りた直後（`map.go` の生成後）は、プレイヤーの立つ部屋に**入った扱いで1回だけ**判定する（今の挙動でもすぐ起きるので、ここは変えすぎない）。
- 中断セーブからの再開時は、前のターンの部屋を**今の部屋で初期化**する（再開しただけでは判定しない）。セーブ形式は変えない。
- 隣接の判定（`enemy_ai.go` の `actEnemy` → `WakeUpSleepingEnemyByProximity`）は**今のまま**（隣接している間、敵の行動ごとに50%。開発者の決定、2026-10-15）。
- 攻撃で必ず起きる判定は、今は近接攻撃（`action.go` の `WakeUpSleepingEnemyByAttack`）からしか呼ばれていない。投げた道具（`item.go` の `applyDamageToEnemy`）・杖・カードなどで仮眠の敵にダメージを与えても起きない可能性が高い。**`applyDamageToEnemy`（`gamehelpers.go`）の中で仮眠を解く**ようにし、プレイヤー由来のダメージの経路をまとめて直す。`Health -=` で直接減らしている箇所（`itemeffects.go` など）も `grep` で洗い出し、プレイヤーの攻撃によるものは同じく起こす。
  - 通常の睡眠（`Sleep > 0`、睡眠のカード・罠）は対象外。ダメージで起こすかどうかは今の挙動を変えない。

### テスト（`sleep_wake_test.go` を新しく作る）

- プレイヤーが同じ部屋に入ったターンだけ判定され、その後部屋にとどまって何ターン経っても（別の敵を攻撃しても）起きない。乱数を固定して「入ったターンに外れた敵は、部屋にいる間ずっと仮眠のまま」を確かめる。
- 部屋を出て入り直すと再び判定される。
- 隣接時の判定は今までどおり働く。
- 近接攻撃・投げた道具・杖の魔法弾で仮眠の敵にダメージを与えると必ず起きる。
- 中断セーブ→再開で仮眠の敵が起きない。

## 2. 足元のアイテムの説明を開いたまま C キーで閉じると説明が残る

### 現象

足元メニュー →「説明」で説明ウィンドウを開き、C キー（すべて閉じる）を押すと、メニューは消えるが説明ウィンドウが画面に残る。

### 原因

`main.go` の `Update` は `handleInventoryInput` を `HandleGroundItemInput` より先に呼ぶ。`handleInventoryInput`（`input.go`）の C キーの処理は `ShowGroundItem` などを false にするが、`showGroundItemDescription`・`groundItemDescriptionText`・`groundMenuJustOpened` を戻していない。そのあと `HandleGroundItemInput` の C キーの処理は `ShowGroundItem` が true の時だけ動くので、もう実行されない。説明ウィンドウ（`draw_ui.go` の `drawGroundItemDescription`）は `ShowGroundItem` を見ずに描くので残る。

### 修正

- 「すべてのウィンドウを閉じる」処理を1つの関数（`closeAllMenus()` など）にまとめ、C キーの処理はすべてそれを呼ぶ。足元の説明・アイテムの説明・足元メニュー・持ち物・行動メニュー・識別や壺の対象選択などの状態をすべて戻す。`HandleGroundItemInput` の C キーの処理も同じ関数に置き換える（重複をなくす）。
- `input.go` の他の C キーの処理（`grep -n "JustPressed(KeyC)"`）も見て、同じように閉じ残しがないか確かめる。白紙のカードの書き込み画面のように C を受け付けない画面は今のまま。
- 念のため、`drawGroundItemDescription` は `ShowGroundItem` が false なら描かないようにする（状態の戻し忘れがあっても画面に残らない）。

### テスト（`regression_test.go` に追加）

- 足元メニュー→説明→C で、`showGroundItemDescription` が false・説明テキストが空・メニューがすべて閉じている。
- 持ち物→アイテム→説明→C でも同じくすべて閉じる。
- 閉じた直後に足元メニューを開き直すと、説明ではなく通常のメニューから始まる。

## 3. 「投げる」の射線が行動メニューに隠れて見えない

### 現象

持ち物からアイテムを選び、行動メニューで「投げる」（矢の「撃つ」、杖の「使う」も同じ）にカーソルを合わせると射線が表示されるが、プレイヤーが見えない。

### 原因

プレイヤーは画面の中央（640×480 の中央付近、`main.go` の `centerX/centerY`）に描かれ、射線は最大10マス（300px）伸びる。その上に次のウィンドウが重なる（描画順は `main.go` の `Draw`）。

- 持ち物のウィンドウ（`drawInventoryWindow`）: 中央に 400×300、背景の不透明度 127
- 行動メニュー（`drawActionMenu`）: 中央に 200×100、背景の不透明度 **255**（完全に不透明）で、プレイヤーと周囲のマスを丸ごと隠す

足元メニュー（`DrawGroundItem`、中央に名前 400×26 と行動 100×110）も同じ理由で、足元の道具を「投げる」時の射線が見えない。

### 修正（開発者の決定、2026-10-15。実機で見て改めて調整することがある）

- 射線のプレビューが出ている間（`trajectoryPreviewSpec` の `active` が true の間）は、
  - 持ち物のウィンドウを描かない（選んでいるアイテムの名前だけ、画面上端の小さいウィンドウに出す）。
  - 行動メニューを**画面の右端**（プレイヤーと射線に重ならない位置、例: 右上の余白）へ寄せて描く。足元メニューも同じ位置へ寄せる。
- プレビューが出ていない項目（「装備」「置く」「説明」など）では今の配置のまま。カーソルを上下するたびにメニューが動くと見づらい場合は、行動メニューを**常に**右端へ置く形にしてよい（見た目で判断し、報告に書く）。
- 位置はウィンドウの大きさから計算し、640×480 の画面からはみ出さないこと。HUD・メッセージ欄と重ならないこと。

### 同じ箇所の付随の不具合（見つけたので一緒に直す）

- `trajectoryPreviewSpec`（`draw.go`）は「投げる」を**2番目（index 1）と決め打ち**している。壺（入れる・出す・投げる…）とかじれる武器（装備・かじる・投げる…）では「投げる」が3番目なので、「出す」「かじる」で射線が出て、「投げる」では出ない。`currentItemActions()` の項目名から「投げる」「撃つ」「使う（杖）」を判定する形に直す。足元メニューの index 決め打ちも同様に見直す。
- 行動メニューの高さ 100 に対して項目は最大5つ（20px 間隔）で、5つ目が枠の下端にかかる。項目数から高さを計算する。

### テスト

- 描画そのものは自動テストしにくいので、配置の計算を関数（`actionMenuRect(screenW, screenH, previewActive)` など）に切り出し、プレビュー中の行動メニューの矩形がプレイヤーのマス（画面中央）と射線の範囲に重ならないことをテストする。
- 壺・かじれる武器・矢・杖・ふつうの道具それぞれで、射線が「投げる」「撃つ」「使う（杖）」の時だけ出ることをテストする。

## 決定事項（開発者、2026-10-15）

1. 隣接による目覚めは「隣にいる間、毎ターン50%」のまま変えない。
2. 射線の見せ方は「射線が出ている間は持ち物のウィンドウを隠し、行動メニューを画面の右端へ寄せる」案で進める。実機で見て、必要なら別の案（背景を半透明にする、プレビュー中だけメニューを消す）に切り替える。
