# バランス基盤: レベル上限99と1〜30階の強さの曲線（Claude Code 用作業指示書）

担当: Claude Code（master で直列に進める。バランスの土台なので並列にしない）
前提: `AGENTS.md`、`docs/agents/README.md`、`docs/agents/STATUS.md` を読んでから始める。

## 背景（2026-10-13 のレポート `reports/baseline.json` より）

- 最も強い BOT（expert）は死亡時の平均レベルが 9.9 で、5〜6階の時点でレベル上限10に張り付き、それ以上強くなれずに死んでいる。
- 現在のレベルの仕組み（`main.go` の `levelExpRequirements`、`move.go` の `checkLevelUp`、`damage.go` の `playerAttackTotal`）:
  - 経験値テーブルはレベル10まで（累計181）。
  - レベルが1上がるごとに最大HP+10。
  - 総攻撃力に**レベルの値がそのまま加算**される（`攻撃力 + パワー + レベル`）。上限を99にすると攻撃力が最大+99され、ダメージ計算が壊れる。
  - 1回の経験値獲得で1レベルしか上がらない。
- 敵は8階相当までしかなく（最大HPは68程度）、9階以降は8階の出現テーブルを使い回している。レベル99にすると、9〜30階は後半ほど簡単になってしまう。

## 進め方

**手順1（設計）を終えたら、実装に入る前に開発者（Ken）へ設計案を提示して確認を取ること。**
数値の決め方はシミュレーションで裏付けを取り、根拠を残す。

### 手順1: 設計（この文書の末尾「決定事項」に書き込む）

1. **レベルの目標曲線**: expert BOT が各階に到達したときの平均レベルの目標を決める。
   仮の目安（開発者が調整する）: 10階で Lv13〜16、20階で Lv22〜26、30階で Lv30〜35。
   Lv99 はやり込みで到達する値とし、通常のクリアでは届かない曲線にする。
2. **経験値テーブル**: Lv99 までの必要経験値を式で生成する（タグなしの純粋関数 + テスト。単調増加、99要素）。
3. **レベルの効果**:
   - 総攻撃力へのレベルの寄与を `levelAttackBonus(level)` のような関数に置き換え、増え方を緩やかにする（線形に +level しない）。
   - 最大HPの増え方を決める（レベルが高いほど1回の上昇量が減るなど）。
   - 1回の経験値獲得で複数レベル上がるようにする。将来の「レベル低下」（ロードマップの状態異常）でも同じ関数を使えるようにする。
4. **9〜30階の敵の強さ**: 次の2段階で進める。
   - **暫定（このタスクで実装）**: 9階以降の敵に、階層に応じた能力値と経験値の補正をかける関数を1か所に作る。`// 暫定: 第3段階の敵を追加したら削除` と明記する。
   - **本番（後続タスクとして指示書を書く）**: 各系統に第3段階（さらに上位の種族）を追加し、1〜30階の出現テーブルを作る。系統をいくつかのグループに分け、Codex で並列に実装できる指示書（`docs/agents/wave2-*.md`）を書く。敵 ID の割り当て範囲も決める。
5. **レポートの追加項目**: 性格ごとに「各階に到達したときの平均レベル」と「死亡時にレベル上限だった割合」を出す。

### 手順2: 実装

- 上の設計を実装する。HUD のレベル表示が2桁になっても崩れないようにする。セーブデータの互換性を確認し、構造が変わる場合は `saveDataVersion` を上げる。
- `levelUpEnemy`（敵が敵を倒して上位種になる仕組み）は別のものなので変えない。
- テスト: 経験値テーブル、複数レベルの一括上昇、レベル99で止まる、`levelAttackBonus` の範囲、階層補正の境界（8階と9階）。

### 手順3: シミュレーションで調整

- `TestSimBatch -sim.runs=1500` を回し、手順1の目標曲線に近づくまで経験値テーブル、敵の経験値、階層補正を調整する。
- 調整のたびに、変えた数値とレポートの要点（クリア率、階ごとの平均レベル、階層別の死亡率、死因の上位）を記録する。
- 目標に近づいたらベースラインを更新してコミットする。
