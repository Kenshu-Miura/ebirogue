# バランス基盤: レベル上限99と1〜30階の強さの曲線（Claude Code 用作業指示書）

担当: Claude Code（master で直列に進める。バランスの土台なので並列にしない）
前提: `AGENTS.md`、`docs/agents/README.md`、`docs/agents/STATUS.md` を読んでから始める。

## 背景（2026-10-13 のレポート `reports/baseline.json` より）

- 最も強い BOT（expert）は死亡時の平均レベルが 9.9 で、5〜6階の時点でレベル上限10に張り付き、それ以上強くなれずに死んでいる。
- 現在のレベルの仕組み（`main.go` の `levelExpRequirements`、`move.go` の `checkLevelUp`、`damage.go` の `playerAttackTotal`）:
  - 経験値テーブルはレベル10まで（累計181）。
  - レベルが1上がるごとに最大HP+10。
  - 総攻撃力に**レベルの値がそのまま加算**される（`攻撃力 + パワー + レベル`）。上限を99にすると攻撃力が最大+99され、ダメージ計算が壊れる。
  - 1回の経験値獲得で1レベルしか上がらない。
- 敵は8階相当までしかなく（最大HPは68程度）、9階以降は8階の出現テーブルを使い回している。レベル99にすると、9〜30階は後半ほど簡単になってしまう。

## 進め方

**手順1（設計）を終えたら、実装に入る前に開発者（Ken）へ設計案を提示して確認を取ること。**
数値の決め方はシミュレーションで裏付けを取り、根拠を残す。

### 手順1: 設計（この文書の末尾「決定事項」に書き込む）

1. **レベルの目標曲線**: expert BOT が各階に到達したときの平均レベルの目標を決める。
   仮の目安（開発者が調整する）: 10階で Lv13〜16、20階で Lv22〜26、30階で Lv30〜35。
   Lv99 はやり込みで到達する値とし、通常のクリアでは届かない曲線にする。
2. **経験値テーブル**: Lv99 までの必要経験値を式で生成する（タグなしの純粋関数 + テスト。単調増加、99要素）。
3. **レベルの効果**:
   - 総攻撃力へのレベルの寄与を `levelAttackBonus(level)` のような関数に置き換え、増え方を緩やかにする（線形に +level しない）。
   - 最大HPの増え方を決める（レベルが高いほど1回の上昇量が減るなど）。
   - 1回の経験値獲得で複数レベル上がるようにする。将来の「レベル低下」（ロードマップの状態異常）でも同じ関数を使えるようにする。
4. **9〜30階の敵の強さ**: 次の2段階で進める。
   - **暫定（このタスクで実装）**: 9階以降の敵に、階層に応じた能力値と経験値の補正をかける関数を1か所に作る。`// 暫定: 第3段階の敵を追加したら削除` と明記する。
   - **本番（後続タスクとして指示書を書く）**: 各系統に第3段階（さらに上位の種族）を追加し、1〜30階の出現テーブルを作る。系統をいくつかのグループに分け、Codex で並列に実装できる指示書（`docs/agents/wave2-*.md`）を書く。敵 ID の割り当て範囲も決める。
5. **レポートの追加項目**: 性格ごとに「各階に到達したときの平均レベル」と「死亡時にレベル上限だった割合」を出す。

### 手順2: 実装

- 上の設計を実装する。HUD のレベル表示が2桁になっても崩れないようにする。セーブデータの互換性を確認し、構造が変わる場合は `saveDataVersion` を上げる。
- `levelUpEnemy`（敵が敵を倒して上位種になる仕組み）は別のものなので変えない。
- テスト: 経験値テーブル、複数レベルの一括上昇、レベル99で止まる、`levelAttackBonus` の範囲、階層補正の境界（8階と9階）。

### 手順3: シミュレーションで調整

- `TestSimBatch -sim.runs=1500` を回し、手順1の目標曲線に近づくまで経験値テーブル、敵の経験値、階層補正を調整する。
- 調整のたびに、変えた数値とレポートの要点（クリア率、階ごとの平均レベル、階層別の死亡率、死因の上位）を記録する。

## 決定事項

2026-10-14 に開発者（Ken）と合意した内容。

### 計測の根拠（expert・上級・400回）

- 現状（Lv上限10）: 到着時の平均レベルは2階 5.8、4階 9.95。以降は上限に張り付く。1階あたりの経験値は 60〜130、10階到着時の累計は約 790。
- 初期HPだけを変えた試作（下記の経験値・レベル効果を仮実装）での1階死亡率と10階到達率:
  HP100: 0.5%・24% ／ HP40: 6%・8% ／ HP25: 15%・3.5% ／ HP15: 38%・0.5%未満。
  敵の攻撃・毒（2×8ターン）・罠の威力が HP100 前提の数値のため、HP15（シレン・トルネコと同じ値）は敵・罠・毒の数値を約0.4倍に縮めないと成立しない。

### 決定

1. **初期HP 40**（案A）。敵・罠・毒の数値は変えない。
2. **目標曲線**（expert の到着時の平均レベル）: 10階 Lv13〜16、20階 Lv22〜26、30階 Lv30〜35。Lv99 はやり込み（累計約47万）。
3. **経験値テーブル**: レベル L に必要な累計 = round(10 × (L−1)^1.5 × 1.04^(L−1))。Lv2=10、Lv5=94、Lv10=384、Lv20=1745、Lv30=4870、Lv99≈47万。1回の獲得で複数レベル上がる（メッセージは最終レベルで1回）。レベルの増減は `setPlayerLevel` を通す（将来のレベル低下も同じ）。
4. **攻撃力**: `levelAttackBonus(L) = round(3√(L−1))`（Lv10 +9、Lv30 +16、Lv99 +30）。
5. **最大HP**: レベルアップ1回の増加は 到達Lv2〜10 で +8、11〜30 で +5、31〜60 で +3、61〜99 で +2（Lv10=112、Lv30=212、Lv99=380）。レベル変化時は差分だけ増減する。
6. **階層による能力値補正は行わない**（開発者判断: 階層で同じ敵の強さが変わるのは良くない）。代わりに**各系統の第3段階の上位種を追加**し、9〜30階の出現テーブルで強さを上げる。2段階目→3段階目も `MonsterLevelUpTable` に登録する。
7. **レポート**: 性格ごとの到着時平均レベル（主要な階）、死亡時にレベル上限だった割合、計測用の不死モード（`-sim.immortal`）による1〜30階の到着時レベル曲線。

### 実装と調整の記録（2026-10-14）

- 実装: `leveling.go`（経験値テーブル・レベル補正・最大HPの増加）、`Player.setLevel` / `checkLevelUp`（move.go）、初期HP 40。第3段階の敵 ID 45〜65（`enemies.go`、画像は `tools/third_stage_enemy_images.go` で第2段階の色相を150度回して生成）、9〜30階の出現テーブル `deepFloorSpawnBands`（monster_spawn.go）。セーブの構造は変えていない（`saveDataVersion` 据え置き）。
- 指示書の「本番（後続タスク）」だった第3段階の敵と1〜30階の敵テーブルは、決定事項6によりこのタスクで実装した。wave2 の敵追加の指示書は不要になった（新系統を足すときは ID 66〜）。
- 第3段階の能力値: 第2段階の HP×1.7・攻撃×2・防御+2。経験値は ×3 → **×2.5** に調整（下表）。遠距離攻撃の威力: ハリセンコウテイ 20、イワヤマガニ 26、メガトンウニ 34、レンゴクイカ 32、ケンジャクラゲ 34。

| 計測（expert・上級） | 10階 | 15階 | 20階 | 25階 | 30階 |
|---|---:|---:|---:|---:|---:|
| 不死モード、第2段階のみ（第3段階の追加前） | 18.6 | 24.8 | 26.8 | 29.9 | 31.1 |
| 不死モード、第3段階 経験値×3 | 19.2 | 27.2 | 33.6 | 42.1 | 47.4 |
| 不死モード、第3段階 経験値×2.5（採用） | 18.8 | 26.5 | 32.5 | 40.6 | 45.7 |

- 不死モードの BOT は HP が減っても戦い続けるので、通常の BOT より敵を多く倒す。両方のデータがある階で比べると通常の BOT のレベルは5階で約0.88倍、7階で約0.75倍。0.75倍で換算すると採用値は 10階 Lv14、20階 Lv24、30階 Lv34 前後で、目標曲線の範囲に入る。通常の BOT は10階のボスより先へほとんど進めないので、深い階の比率は**推定**。ボスと難易度の調整で BOT が深く進めるようになったら実測し直す。
- 通常のバッチ（1512回、`reports/baseline.json` を更新）: クリア 0（以前は 1）。expert の平均到達階 5.5〜6.0 → 4.7〜5.1。階層別の死亡率は1階 20.9% → 28.7%、4階 45.3% → 51.4%。死因の上位はエビ、毒ヘビ、イシガニの投石、ハヤテシャコ。**死亡時にレベル上限だった割合は全性格で 0%**（以前の expert は死亡時 Lv9.9 で上限に張り付いていた）。
- 序盤の死亡率が上がったのは初期HPを40に下げたため（決定事項1で想定済み）。クリア率の調整は wave2-backlog の5（難易度ごとのクリア率目標に合わせたテーブル調整）とボス（wave1-C）で行う。

### 残った課題

- ~~wave1-B のダメージ罠（木の矢12・鉄の矢24・落石30）は「初期HP100に対して1〜2割」を基準に決めた威力。初期HP40では落石が序盤のHPのほぼ全部になるので、罠の出現階か威力の見直しが必要~~ → **2026-10-14 に見直し済み**（`trap_damage.go`）。
  - **威力**: 木の矢 12→**6**、鉄の矢 24→**12**、落石 30→**16**。毒は毎ターン 2→**1**（`poisonDamagePerTurn`。毒矢の罠の5ダメージ・8ターンは据え置き）。地雷（現在HPの1/2）・大型地雷（3/4）は割合ダメージなので変えない。
  - **基準**: Lv1（最大HP40・防御3、軽減 (15/16)^3≈0.82）で、満タンから1回踏んでも半分は残ること。落石は平均13（33%）・最大15（37%）、鉄の矢は平均10（25%）、木の矢は平均5（12%）。旧値は落石が平均25（62%）・最大28（70%）で、HP15〜25 で踏むと即死だった。毒矢は 5+2×8=21（53%）→ 5+1×8=13（33%）で落石と同程度。
  - **成長との関係**（`levelHealthBonus`、防御3のまま・落石の平均）: Lv5（HP72）18%、Lv10（HP112）12%、Lv14（HP132、10階の到着時）10%、Lv24（HP182、20階）7%、Lv34（HP224、30階）6%。防具で防御が上がるとさらに下がる。
  - **固定値のままにした理由**: (1) 階層で威力を変える案は、同じ罠の強さが階で変わることになり「階層で能力値を補正しない」方針（決定事項6）と合わない。(2) 罠が出る階で抑える案（落石は〇階から、など）は階層別の罠出現テーブル（ロードマップ Priority B、`wave2-backlog.md` の5）で扱う。`maptraps.go` の罠テーブルは wave2-A と並行中のため今回は触らない。(3) 固定値の物理罠は序盤〜中盤の脅威という位置づけにし、深い階の罠の脅威は割合ダメージの地雷・大型地雷と状態異常の罠が担う。深い階でも意味のある量にしたい場合は、階層別の罠テーブルで深い階だけに出る強い罠（新しい ID）を追加する。
  - **シミュレーション**（1512回、変更前の `reports/baseline.json` との比較。ベースラインは更新済み）: 罠と毒による死亡は 111 → 46（落石 31→13、毒 29→9、鉄の矢 25→7、木の矢 16→5、毒矢の罠 4→2、大型地雷 6→9）。階層別の死亡率は 1階 28.7%→26.5%、2階 29.7%→28.9%、3階 43.5%→42.1%、4階 51.4%→50.4%。死因の上位はエビ 190→195、毒ヘビ 160→166、イシガニの投石 156→157、ハヤテシャコ 116→109 で変わらず（序盤の死亡の主因は敵）。expert の平均到達階は +0.18〜+0.42、初級 expert が1回クリア（0→1）。
