# wave9-A: 階層別のアイテム・罠の出現テーブル（Claude Code 用）

ブランチ: `agent/wave9-A-floor-tables`
前提: **段8（wave8-A/B/C）が master に統合されていること**（全アイテムがそろってから重みを決める）。wave9-C（壺 225〜239）と並行するので、9-C の ID は表に入れておき、テンプレートが無い ID は読み飛ばす形にする。`AGENTS.md`、`docs/agents/README.md`、`docs/agents/STATUS.md`、`docs/agents/feature-completion-plan.md` を先に読む。

## 目的

今は全階で同じ重みでアイテムと罠が出る（カテゴリの重み `itemCategorySpawnWeights` とカテゴリ内の重み `itemSpawnWeights`、罠は `floorTrapIDs`）。敵は1〜30階の表がある（`FloorSpawnTables`）。アイテムと罠も階層別にし、wave11 のクリア率の調整（初級85%・中級50%・上級10%、`feature-completion-plan.md`）で動かす**つまみ**を用意する。**このタスクでクリア率を合わせにいかない。**

## 作るもの

1. **アイテムの階層別の重み**（タグなしの純粋なファイル、例 `item_floor_tables.go`）:
   - カテゴリの重みを階の帯（1〜3・4〜8・9〜12・13〜16・17〜20・21〜25・26〜30。敵の `deepFloorSpawnBands` に合わせる）ごとに持つ。
   - テンプレートごとに「出始める階」「出なくなる階」「重み」を持てるようにする（書いていない道具は全階・重み1。今の挙動と同じ）。強い道具（強化値の高い武具、無敵の薬、全滅・ジェノサイドのカードなど）は出始める階を遅らせる。
   - カードの出現率（AGENTS.md「Priority A: cards」の「あかり・真空斬りを含めて階層別出現テーブル導入時に出現率を調整」）をここで決める。
2. **罠の階層別の重み**: 浅い階はダメージの小さい罠、深い階で大型地雷・鉄の矢・落石・回復封じなどが増える。ボス階・30階で落とし穴を除く規則（`availableTrapIDs`）は残す。
3. **難易度ごとの補正のつまみ**（値はすべて 1.0 ＝補正なしで入れる）: 難易度ごとに「食料・回復薬の重みの倍率」「強い道具の重みの倍率」「1階あたりの道具の数」「罠の数」を変えられる表。wave11 で値を入れる。
4. **wave2-A の仮の値の見直し**: 散乱の最大3個・腐ったウインナーの回復10・パワー1減少・3罠の不発率20%を、表に移して根拠を書く（値は変えなくてよい）。
5. `TestItemCategorySpawnWeights` を階層別に拡張する（どの階でもすべてのカテゴリが出る、出始める階が出なくなる階より前、など表の健全性）。BOT のレポートの「床の道具（各階の到着時、種類別）」が階の帯ごとに見えるようにする。

## 守ること

- 床の道具の抽選はフロア生成の乱数（`newFloorRNG`）のままにする。
- 重みの初期値は「今の割合から大きく変えない」こと。導入前後で `TestSimBatch -sim.runs=1500 -sim.difficulty=all` を比べ、expert のクリア率・餓死・平均到達階の差が1区分84冒険のばらつきの範囲（目安 ±5pt）に収まるようにする。外れたら原因と案を完了報告に書く。
- 店（wave10-B）の品ぞろえも同じ表を使えるよう、「階と乱数を受け取って道具の ID を返す関数」として公開する。
